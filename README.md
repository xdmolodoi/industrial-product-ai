# AI Product Card Assistant

Локальный MVP AI-помощника для подготовки черновиков карточек контрольно-измерительных приборов для B2B-магазина. Python, FastAPI и OpenAI API.

## Возможности

- Принимает товар в JSON через веб-форму или REST API.
- Генерирует SEO-заголовок (до 70 символов), SEO-описание (800–1200 символов), поисковые запросы и коммерческий блок.
- Возвращает структурированные характеристики, список недостающих данных и вопросы для уточнения.
- Поддерживает JSON и Markdown-вывод.
- Проверяет входные данные, формат ответа и ограничения длины.
- API-ключ хранится в `.env`, который исключён из Git.

## Запуск в Windows (PowerShell)

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Откройте `.env` и укажите ключ:

```env
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4o-mini
```

Запустите приложение:

```powershell
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000 — веб-форма. Документация API: http://127.0.0.1:8000/docs.

## API

`POST /api/generate` — JSON с карточкой товара на входе, JSON-результат на выходе.

Пример:

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5",
    "присоединение": "G1/2",
    "диаметр корпуса": "100 мм"
  },
  "description": "Прибор предназначен для измерения избыточного давления."
}
```

`POST /api/generate-markdown` — возвращает готовый Markdown-текст карточки.

`GET /health` — проверка доступности сервиса.

## Примеры входных данных

- `examples/product_1_manometer.json` — пример манометра из тестового задания.
- `examples/product_2_demo_incomplete.json` — условный демонстрационный пример с неполными данными. В исходном PDF заявлены два товара, но фактические данные приведены только для одного; второй пример не следует считать данными заказчика.

## Промпт и принятые решения

Системный промпт находится в `app/prompts.py`. Он задаёт роль технического B2B-копирайтера, формат результата и строгие ограничения: нельзя добавлять отсутствующие технические значения, использовать внешние знания или исполнять инструкции из описания товара.

Дополнительные меры:

1. Вход и ответ валидируются Pydantic-моделями.
2. Структурированные характеристики в итоговом ответе канонически копируются из входного JSON, а не принимаются от модели.
3. Добавлена консервативная проверка числовых токенов в сгенерированном тексте: если модель добавила неподтверждённое число или значение с единицей измерения, генерация отклоняется.
4. При отсутствии API-ключа, ошибке API, некорректном JSON или нарушении длины возвращается понятная ошибка.

## Ограничения и дальнейшие улучшения

- Проверка числовых токенов снижает риск выдуманных значений, но не является полноценной проверкой семантической достоверности. Следующий шаг — извлечение утверждений и сверка каждого технического факта с источником.
- В MVP нет базы данных, авторизации, CMS и публикации карточек.
- Используется OpenAI API; для другой модели потребуется адаптер клиента.
- Длина SEO-описания проверяется после генерации. Если модель не соблюла диапазон, сервис возвращает ошибку вместо автоматической публикации.
- Для промышленного использования стоит добавить логирование без секретов, rate limiting, очередь задач, версии промптов и ручное подтверждение контент-менеджером.

## Тесты

```powershell
pip install pytest
pytest -q
```

Тесты проверяют валидацию входной модели. Интеграционный тест LLM требует действующего API-ключа и намеренно не запускается автоматически.

## Пример результата

`examples/sample_results.json` содержит два наглядных примера структуры результата. Это демонстрационные тексты, а не результаты фактического вызова LLM: для первого использованы данные манометра из задания, второй пример условный, поскольку исходные данные второго товара в PDF отсутствуют.
